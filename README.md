# PhotoRank 📸

Сайт для коллективного оценивания фотографий с тир-листом.

## Стек
- **Бэкенд**: Python + FastAPI
- **БД**: SQLite (WAL-режим, держит 20к+ записей легко)
- **Аутентификация**: JWT + bcrypt
- **Деплой**: Docker / docker-compose

---

## Быстрый старт

### 1. Установите Docker и docker-compose
```bash
# Ubuntu/Debian
curl -fsSL https://get.docker.com | sh
sudo apt install docker-compose-plugin
```

### 2. Клонируйте / распакуйте проект
```bash
cd photorank
```

### 3. Задайте секретный ключ
Откройте `docker-compose.yml` и замените `JWT_SECRET` на случайную строку:
```yaml
JWT_SECRET: СУПЕР_СЕКРЕТНАЯ_СТРОКА_МИНИМУМ_32_СИМВОЛА
```

### 4. Запустите
```bash
docker compose up -d --build
```

Сайт будет доступен на `http://localhost:8000`

## Загрузка фотографий

**Вариант 1 — через интерфейс (рекомендуется для < 1000 фото)**
1. Войдите как администратор
2. Нажмите иконку ⚙️ → Панель администратора
3. Перетащите файлы в зону загрузки (поддерживается выбор тысяч файлов)

**Вариант 2 — напрямую в папку (для 20к фото)**
```bash
# Скопируйте все фото в папку photos/
cp /ваша/папка/*.jpg ./photos/
cp /ваша/папка/*.jpg ./photos/

# Затем зарегистрируйте их в БД одной командой:
docker compose exec app python3 -c "
import os, sqlite3, uuid
db = sqlite3.connect('/app/data/db.sqlite3')
photos_dir = '/app/photos'
files = [f for f in os.listdir(photos_dir) if f.lower().endswith(('.jpg','.jpeg','.png','.webp'))]
existing = {r[0] for r in db.execute('SELECT filename FROM photos')}
added = 0
for i, f in enumerate(sorted(files)):
    if f not in existing:
        db.execute('INSERT INTO photos (filename, original_name, position) VALUES (?,?,?)', (f, f, i))
        added += 1
db.commit()
print(f'Добавлено {added} фотографий')
"
```

## Процесс работы

1. Пользователи **регистрируются** на сайте
2. Все видят **одну и ту же** фотографию в данный момент
3. Каждый ставит оценку **от 1 до 5 звёзд**
4. **Администратор** переключает фото кнопками «Вперёд / Назад»
5. После оценки всех фото открывается **тир-лист**:
   - **S** — средняя 4.5–5.0 ★
   - **A** — средняя 3.5–4.5 ★
   - **B** — средняя 2.5–3.5 ★
   - **C** — средняя 1.5–2.5 ★
   - **D** — средняя 0–1.5 ★

## Автотегирование фото (WD14)

При загрузке каждое новое фото (через интерфейс, импорт с Яндекс.Диска или
авто-синхронизацию) автоматически прогоняется через локальную модель
**WD14 ConvNextV2** — без обращения к каким-либо внешним API, полностью
офлайн, на CPU.

Важно: распознанные теги — это **предложения**, а не сразу готовые теги
фото. На экране голосования они показываются в общем списке тегов с
пометкой **AI** и двумя кнопками — ✓ подтвердить, ✕ отклонить. Подтверждения
любого одного человека достаточно, чтобы тег сразу стал обычным — появился
в тир-листе, фильтрах по тегам и счётчиках. Пока никто не подтвердил —
предложенный тег не учитывается ни в тир-листе, ни в фильтрах: модель может
ошибаться, и финальное решение остаётся за людьми.

Если модель не установлена или распознавание не удалось — фото всё равно
загружается, просто без предложенных тегов. Это не блокирующая операция.

### Установка модели

1. Скачайте 2 файла со страницы модели на HuggingFace:
   **https://huggingface.co/SmilingWolf/wd-v1-4-convnextv2-tagger-v2/tree/main**
   - `model.onnx` (~380 МБ)
   - `selected_tags.csv`
2. Положите оба файла в папку `wd14_model/` в корне проекта (рядом с `docker-compose.yml`):
   ```
   photorank/
   ├── wd14_model/
   │   ├── model.onnx
   │   └── selected_tags.csv
   ```
3. Перезапустите контейнер:
   ```bash
   docker compose restart
   ```

Эта папка подключена как volume, так что для смены/обновления модели достаточно
заменить файлы и перезапустить контейнер — пересборка образа не требуется.

Список тегов, которые модель умеет распознавать, должен совпадать по `tag_id`
с тем, что уже загружен в БД из `tags.csv` (это тот же формат `selected_tags.csv`
от SmilingWolf, так что они совместимы «из коробки»).

Технически предложенные теги хранятся в той же таблице `photo_tags`, что и
обычные, от имени системного аккаунта `auto-tagger` (с флагом `is_suggestion=1`
до подтверждения). Этот аккаунт не виден в списках участников и не считается
в статистике голосования.

## Импорт и авто-синхронизация с Google Диска

Помимо Яндекс.Диска, можно подключить публичную папку Google Диска (доступ
«у кого есть ссылка») — включая вложенные подпапки, все фото из них собираются
в общий список без сохранения структуры папок.

### Настройка

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект
   (или используйте существующий), включите **Google Drive API**
   (APIs & Services → Library → Google Drive API → Enable).
2. Создайте API-ключ: APIs & Services → Credentials → Create Credentials →
   API key. Ограничивать ключ доменом не нужно — он используется только
   с сервера, не в браузере.
3. Добавьте ключ в `docker-compose.yml`:
   ```yaml
   environment:
     - GOOGLE_DRIVE_API_KEY=ваш_ключ_сюда
   ```
4. Откройте нужную папку на Google Диске → Поделиться → измените доступ на
   **«Все, у кого есть ссылка»** (роль «Читатель» достаточно). Это нужно
   сделать и для самой папки, и убедиться, что вложенные подпапки не имеют
   более строгих ограничений доступа.
5. Перезапустите контейнер и вставьте ссылку на папку в админ-панели,
   в карточке «Импорт с Google Диска» или «Авто-синхронизация с Google Диском».

Без заданного `GOOGLE_DRIVE_API_KEY` обе функции (импорт и автосинхронизация)
просто вернут понятную ошибку — остальная часть сайта продолжит работать
как обычно.
