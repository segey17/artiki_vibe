# PhotoRank 📸

Сайт для коллективного оценивания фотографий тир-листами. Любой
зарегистрированный человек может создать свою **сессию оценивания** со
своими тирами и своей подборкой фото, пригласить других по коду или
названию — и получить общий тир-лист по итогам голосования. Есть отдельная
**галерея** для просмотра всех фото без привязки к какой-либо сессии,
**автотегирование** фото локальной ИИ-моделью (с подтверждением тегов
людьми, а не вслепую), и **профили** участников с их личной статистикой.

## Стек
- **Бэкенд**: Python + FastAPI, WebSocket для живых обновлений (смена фото, голоса, теги)
- **БД**: SQLite (WAL-режим)
- **Аутентификация**: JWT + bcrypt
- **Автотегирование**: WD14 (SmilingWolf, семейство v3) через ONNX Runtime, полностью офлайн на CPU
- **Деплой**: Docker / docker-compose

## Быстрый старт

### 1. Установите Docker и docker-compose
```bash
# Ubuntu/Debian
curl -fsSL https://get.docker.com | sh
sudo apt install docker-compose-plugin
```

### 2. Распакуйте проект
```bash
cd photorank
```

### 3. Задайте секретный ключ
Откройте `docker-compose.yml` и замените `JWT_SECRET` на случайную строку
минимум 32 символа:
```yaml
environment:
  - JWT_SECRET=СУПЕР_СЕКРЕТНАЯ_СТРОКА_МИНИМУМ_32_СИМВОЛА
```

### 4. Запустите
```bash
docker compose up -d --build
```

Сайт будет доступен на `http://localhost:8000`

### 5. Создайте администратора
```bash
docker compose exec app python3 create_admin.py admin ВАШ_ПАРОЛЬ
```
Повторный запуск с тем же именем просто обновит пароль и права — можно
использовать и для того, чтобы вернуть себе админку, если что-то пошло не так.

## Как это устроено

После входа человек попадает в **галерею** — это главная страница сайта.
Оттуда можно:

- открыть **«Сессии»** — список активных сессий оценивания, с поиском по
  названию и кнопкой создать свою;
- открыть **«Участники»** — список всех зарегистрированных людей, из
  которого можно зайти в профиль любого из них;
- открыть свой **профиль**, кликнув по своему имени в шапке;
- посмотреть **«Тир-лист»** — официальный тир-лист, который админ сайта
  опубликовал на главную (снимок какой-то сессии на момент публикации);
- зайти в **«Управление фото»** (если есть права).

### Сессии оценивания

Любой зарегистрированный человек может создать сессию:

1. **Название** сессии.
2. **Какие фото включить** — на выбор карточками-альбомами:
   - «Все фото»;
   - «Новые фото» — те, которых ещё нет в текущем опубликованном на главной
     тир-листе;
   - один или несколько **тегов** — можно выбрать сразу несколько карточек,
     тогда в сессию попадут только фото, у которых есть **все** выбранные
     теги одновременно (логика «И», а не «ИЛИ»). Отдельным переключателем
     можно включить в подборку фото, у которых тег стоит только как
     неподтверждённое предложение автотегирования.
3. **Тиры** — свои названия, цвета, от 2 до 10 штук (по умолчанию S/A/B/C/D,
   но можно переименовать/перекрасить/добавить/удалить любой).
4. Перемешать порядок фото — по желанию.

Создатель сессии становится её «админом» — только он (или сайт-админ) может
листать фото вперёд/назад, перемешивать, включать авто-переход (когда все
подключённые онлайн проголосовали — сессия сама переходит к следующему фото)
и завершить сессию, когда она больше не нужна (завершённые сессии пропадают
из общего списка, но данные не удаляются).

Присоединиться к чужой сессии можно из общего списка (с поиском по
названию) или по прямой ссылке вида `http://ваш-сайт/#код_сессии`.

Внутри сессии есть свой тир-лист, статистика по каждому участнику (сколько
проголосовал, любимые теги, распределение оценок) и сравнение с любым другим
участником этой же сессии (насколько совпадают оценки).

### Галерея

Отдельный, не привязанный к сессиям экран — все фото на сайте, только для
просмотра (без права поставить оценку). Разбита на «выпуски» по несколько
десятков фото за раз (число подстраивается под ширину экрана, чтобы ряды
были полными), с плавающей панелью навигации внизу экрана и кнопкой
**🎲 «Случайный выпуск»** — быстро прыгнуть в случайную пачку фото вместо
пролистывания по порядку.

Фильтр по тегу в боковой панели работает так же, как при создании сессии —
можно выбрать сразу несколько тегов (фото должно иметь все сразу), и отдельно
включить показ неподтверждённых AI-тегов. Открыв фото крупным планом, можно
видеть его теги и подтверждать/отклонять предложения автотегирования — но
не добавлять свои теги вручную (это можно только на экране голосования внутри
сессии).

### Официальный тир-лист

Сайт-админ может опубликовать тир-лист любой сессии (активной или уже
завершённой) на отдельную вкладку, доступную всем с главной страницы. Это
именно **снимок** на момент публикации — если в исходной сессии продолжат
голосовать, опубликованная версия не обновится сама, нужно опубликовать
её заново.

### Теги

Теги — общий атрибут фото, не привязанный к конкретной сессии: если тег
подтверждён на каком-то фото, он виден отовсюду (в галерее, в любой сессии,
в фильтрах). Везде, где показываются теги, они разделены на две группы —
**🎭 Персонажи** и **🏷️ Общие теги** (по категории из словаря WD14).

Кто угодно может добавить свой тег вручную на экране голосования. Все
изменения тегов (добавление, подтверждение, отклонение, удаление)
рассылаются остальным подключённым людям по WebSocket сразу — не нужно
обновлять страницу, чтобы увидеть, что кто-то подтвердил тег.

### Профили и участники

У каждого человека есть глобальный профиль (не привязан к одной сессии):
сколько оценок поставлено, в скольких сессиях участвовал, сколько сессий
создал, сколько тегов добавил вручную, какая доля оценок пришлась на
верхнюю половину тиров, и список любимых тегов (по тегам самых высоко
оценённых им фото). Открыть профиль можно кликом по своему имени в шапке,
или через список «Участники» — профиль любого человека открыт для просмотра
всем зарегистрированным.

## Управление фото

Раздел доступен всем зарегистрированным (кроме полного сброса базы —
только сайт-админам):

- **Загрузка** — перетащить файлы в браузере, с индикатором прогресса.
- **Сканирование папки на сервере** — если фото скопировали на сервер
  напрямую (`scp`, `docker cp`, для больших партий в тысячи файлов), кнопка
  найдёт файлы, которых ещё нет в базе, зарегистрирует их и запустит
  автотегирование — без необходимости лезть в консоль сервера.
- **Импорт и авто-синхронизация** с Яндекс.Диска и Google Диска (публичные
  папки, включая вложенные подпапки) — см. отдельный раздел ниже про Google Диск.
- **Поиск дублей** — по имени файла (последствие гонки при параллельной
  синхронизации) и отдельно **по содержимому самой картинки** (перцептивный
  хеш — находит одно и то же изображение под разными именами, даже в другом
  формате или с другим размером). Второй вариант не запускается
  автоматически — только по кнопке, так как первый прогон считает хеш
  каждого фото и может занять время.
- **Статус автотегирования** — какая модель загружена и её размер на диске.
- **Полный сброс базы** (только сайт-админ) — удаляет всех обычных
  пользователей, все фото, голоса, теги, все сессии и опубликованный
  тир-лист.

## Автотегирование фото (WD14)

При загрузке каждое новое фото (через интерфейс, импорт с Яндекс.Диска,
Google Диска или сканирование папки) автоматически прогоняется через
локальную модель семейства **WD14 v3** (SmilingWolf) — без обращения к
каким-либо внешним API, полностью офлайн, на CPU.

Важно: распознанные теги — это **предложения**, а не сразу готовые теги
фото. Они показываются в общем списке тегов с пометкой **AI** и двумя
кнопками — ✓ подтвердить, ✕ отклонить. Подтверждения любого одного человека
достаточно, чтобы тег сразу стал обычным — появился в тир-листе, фильтрах
по тегам и счётчиках. Пока никто не подтвердил — предложенный тег не
учитывается ни в тир-листе, ни в фильтрах: модель может ошибаться, и
финальное решение остаётся за людьми.

Если модель не установлена или распознавание не удалось — фото всё равно
загружается, просто без предложенных тегов. Это не блокирующая операция.

При массовой загрузке (импорт с диска, авто-синхронизация, сканирование
папки на сервере) все новые фото прогоняются через модель одним батчем,
а не по одному — на CPU это заметно быстрее суммарно, чем по одному фото
за раз, за счёт амортизации накладных расходов на вызов модели.

### Установка модели

1. Скачайте 2 файла с одной из моделей семейства v3 на HuggingFace. Есть выбор
   между точностью и скоростью — все варианты работают с этим кодом без
   изменений, просто замените файлы:
   - **https://huggingface.co/SmilingWolf/wd-vit-tagger-v3/tree/main** — лёгкая
     и быстрая, хороший вариант по умолчанию для CPU-сервера (~380 МБ)
   - **https://huggingface.co/SmilingWolf/wd-swinv2-tagger-v3/tree/main** —
     чуть точнее, чуть тяжелее
   - **https://huggingface.co/SmilingWolf/wd-eva02-large-tagger-v3/tree/main** —
     самая точная модель в семействе на сегодня, но и самая медленная на CPU;
     имеет смысл, только если точность важнее скорости и сервер достаточно мощный
   - из каждой нужны файлы `model.onnx` и `selected_tags.csv`
2. Положите оба файла в папку `wd14_model/` в корне проекта (рядом с `docker-compose.yml`):
   ```
   photorank/
   ├── wd14_model/
   │   ├── model.onnx
   │   └── selected_tags.csv
   ```
3. Перезапустите контейнер:
   ```bash
   docker compose restart
   ```

Эта папка подключена как volume, так что для смены/обновления модели достаточно
заменить файлы и перезапустить контейнер — пересборка образа не требуется.

Список тегов, которые модель умеет распознавать, должен совпадать по `tag_id`
с тем, что уже загружен в БД из `tags.csv` (это тот же формат `selected_tags.csv`
от SmilingWolf, так что они совместимы «из коробки»).

### Настройка производительности

Через переменные окружения (в `docker-compose.yml`) можно подстроить пороги
уверенности и размер батча без изменения кода:

```yaml
environment:
  - WD14_GENERAL_THRESHOLD=0.40   # порог для общих тегов (по умолчанию 0.40)
  - WD14_CHARACTER_THRESHOLD=0.50 # порог для тегов-персонажей (по умолчанию 0.50)
  - WD14_BATCH_SIZE=8             # сколько фото прогонять за один проход модели
```

`WD14_BATCH_SIZE` — компромисс между скоростью и памятью: больше значение
эффективнее использует CPU за проход, но требует больше оперативной памяти
на сам батч. 8 — разумное значение по умолчанию для типичного сервера;
если сервер слабый или память ограничена, можно снизить до 2-4.

Технически предложенные теги хранятся в той же таблице `photo_tags`, что и
обычные, от имени системного аккаунта `auto-tagger` (с флагом `is_suggestion=1`
до подтверждения). Этот аккаунт не виден в списках участников и не считается
в статистике голосования.

## Импорт и авто-синхронизация с Google Диска

Помимо Яндекс.Диска, можно подключить публичную папку Google Диска (доступ
«у кого есть ссылка») — включая вложенные подпапки, все фото из них собираются
в общий список без сохранения структуры папок.

### Настройка

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект
   (или используйте существующий), включите **Google Drive API**
   (APIs & Services → Library → Google Drive API → Enable).
2. Создайте API-ключ: APIs & Services → Credentials → Create Credentials →
   API key. Ограничивать ключ доменом не нужно — он используется только
   с сервера, не в браузере.
3. Добавьте ключ в `docker-compose.yml`:
   ```yaml
   environment:
     - GOOGLE_DRIVE_API_KEY=ваш_ключ_сюда
   ```
4. Откройте нужную папку на Google Диске → Поделиться → измените доступ на
   **«Все, у кого есть ссылка»** (роль «Читатель» достаточно). Это нужно
   сделать и для самой папки, и убедиться, что вложенные подпапки не имеют
   более строгих ограничений доступа.
5. Перезапустите контейнер и вставьте ссылку на папку в «Управление фото»,
   в карточке «Импорт с Google Диска» или «Авто-синхронизация с Google Диском».

Без заданного `GOOGLE_DRIVE_API_KEY` обе функции (импорт и автосинхронизация)
просто вернут понятную ошибку — остальная часть сайта продолжит работать
как обычно.

| Действие | Обычный пользователь | Владелец сессии | Сайт-админ |
|---|---|---|---|
| Голосовать, добавлять/подтверждать теги | ✅ | ✅ | ✅ |
| Создать свою сессию | ✅ | — | ✅ |

## Переменные окружения

| Переменная | Описание | По умолчанию |
|---|---|---|
| `JWT_SECRET` | Секрет для подписи токенов входа — обязательно замените | `change-me-in-production-please` |
| `GOOGLE_DRIVE_API_KEY` | API-ключ для импорта/синхронизации с Google Диска | не задан (функция отключена) |
| `WD14_GENERAL_THRESHOLD` | Порог уверенности для общих тегов автотегирования | `0.40` |
| `WD14_CHARACTER_THRESHOLD` | Порог уверенности для тегов-персонажей | `0.50` |
| `WD14_BATCH_SIZE` | Сколько фото прогонять через модель за один проход | `8` |
